Project Overview — Sporting Club System

📋 This document serves as the Product Requirements Document (PRD) for the full sporting club management platform. It covers 3 systems: Dashboard, Mobile App, and Public Website — all powered by a shared .NET backend.
🎯
Project Vision
What we're building and why
A comprehensive digital platform for a sporting club that digitalizes member management, subscriptions, reservations, and internal services. The platform enables club staff to operate efficiently via a dashboard, provides members with a mobile-first experience, and exposes the club to the public through a marketing website.

Architecture Decision Records

Clean Architecture (.NET) — Domain → Application → Infrastructure → Presentation layers. CQRS pattern with MediatR. Repository pattern with Unit of Work.
JWT + Refresh Tokens — All protected APIs use JWT. Mobile app uses long-lived refresh tokens. Dashboard sessions expire after inactivity.
Push Notifications — Firebase Cloud Messaging (FCM) for Android & iOS. Backend triggers via event-based system. Dashboard controls notification broadcast.
File Storage — Azure Blob Storage (or MinIO self-hosted) for profile images, club assets, store images, and documents.
API Versioning — All endpoints versioned from day 1 (v1/...). Breaking changes never deployed without version bump. Swagger docs auto-generated.
Localization — Arabic + English support across all systems. Backend returns language-aware content. Mobile app has in-app language toggle.
